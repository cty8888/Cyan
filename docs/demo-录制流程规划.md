# 贪吃蛇 Demo 录制流程规划（两轮）

工作区启动：

```bash
cyan -w /home/cty/Demo/snake
```

整体结构：**第一轮做出能跑但简陋的版本 → 退出 → `cyan --continue` 接回同一会话 → 第二轮用 Skills 打磨体验**。
这样两轮之间可以停一下（试玩、剪辑、甚至关终端），不必一直挂着 REPL。

- 第一轮启动：`cyan -w /home/cty/Demo/snake`
- 第二轮启动：`cyan -w /home/cty/Demo/snake --continue`（恢复该工作区最近一次会话）
- 第一轮要粘贴的基础需求：`/home/cty/Demo/snake/01-初始任务.md`（规则已经写细）
- 第二轮只看操作提要、现场手打：`/home/cty/Demo/snake/02-skill优化任务.md`
- 项目级 Skill：`/home/cty/Demo/snake/.cyan/skills/game-juice/SKILL.md`（启动后自动发现）

时间提醒：两轮加起来建议剪成 2.5~3 分钟一条，或上/下集各约 1.5 分钟。
等待模型思考的空白可以加速，工具执行、审批面板、浏览器试玩尽量保留原速。
权限模式用 `default`，这样 `bash` 会弹出审批面板。

下面「要说 / 要打」就是录制时照着做的台词。方框里的文字是敲进 Cyan 的内容；
括号里的是你可以口头带一句的旁白（没有配音也可以不说，只打字也成立）。

## 第一轮：基础版

目标：按 `01-初始任务.md` 做出能玩、能测、界面朴素的版本。
那份文件已经把逻辑写死了，粘贴时不要再口头加规则；手打那句只用来强调「先别打磨」。

`01-初始任务.md` 里约定的核心逻辑（录的时候心里有数，不用念）：

| 项 | 约定 |
|---|---|
| 棋盘 | 20×20 整格，固定 tick（约 150ms），不随得分加速 |
| 蛇 | 队列，index 0 是头；每步先算 `nextHead` 再判定 |
| 转向 | WASD / 方向键；禁止 180 度掉头；同一 tick 只收一次有效转向 |
| 每步顺序 | 转向 → 新头 → 撞墙 → 撞身（按移动前的身体，不做尾巴让位）→ 吃则变长并刷新食物 → 否则头进尾出 |
| 开局 | 长度 3、水平、默认向右；死亡显示得分并可重开 |
| 交付 | `game-logic.js` 纯函数 + `index.html` 画面 + `test.js`（Node `assert`，跑 `node test.js`） |
| 明确不做 | 音效、最高分、渐变、粒子、随分数加速、移动端手势 |

### 步骤 1 · 启动

敲：

```bash
cyan -w /home/cty/Demo/snake
```

画面停 2 秒，让 Banner（模型 / 权限模式 / 工作区）入镜。

可选旁白：「这是 Cyan，一个命令行编程智能体。」

### 步骤 2 · 发任务

打开 `/home/cty/Demo/snake/01-初始任务.md`，从「用纯 HTML」一直复制到文末「完成后告诉我怎么打开 `index.html` 来玩。」，整段粘贴进 Cyan，**先别回车**。

标题 `# 任务 · 第一轮（基础版）` 不用贴。

光标停在末尾，**自己手打**这一句再回车（不要写进 `01-初始任务.md` 一起粘贴）：

```
先做成能玩的就行，界面先别花时间打磨，我等下自己打开浏览器试两把。
```

可选旁白：「先让它按这份规则写一个能玩的版本。」

### 步骤 3 · 看它干活（不用说话）

盯这几件事入镜即可：

| 画面 | 展示的是 |
|---|---|
| 清单逐条打勾 | `todo_write` 任务规划 |
| 创建 `index.html` / `game-logic.js` / `test.js` 的实时预览 | `write_file` |
| 跑 `node test.js` 前弹出边框 | `bash` 安全审批 |

审批出现时敲：

```
y
```

测试全绿停一下。可选旁白：「测试过了。」

### 步骤 4 · 试玩

按它给出的方式打开 `index.html`（一般是浏览器打开该文件）。
玩大约 10 秒：方向键/WASD 走两步、吃食物涨分、再故意撞墙出 Game Over，必要时点重新开始。

可选旁白：「能玩。界面还比较素。」

### 步骤 5 · 收尾

切回终端。任务完成摘要卡片入镜（工具次数 / token / 耗时）。

再敲：

```
/changes
```

看这一轮改了哪些文件。

然后敲：

```
/exit
```

第一轮结束。会话已经写在 `~/.cyan/projects/.../` 里，`--continue` 会把它找回来。

可选旁白：「这轮改了这几个文件。先退出，一会儿接着改。」

## 第二轮：用 Skills 打磨

目标：同一份游戏明显更好看、更好玩。**这一轮不要粘贴长文**，命令和需求全部手打。
操作提要在 `/home/cty/Demo/snake/02-skill优化任务.md`，不要把 Skill 里的 checklist 逐条念出来，交给模型按 Skill 自己发挥。

### 步骤 0 · 接上第一轮会话

第一轮已经 `/exit` 的话，用 `--continue` 恢复本工作区最近一次会话（必须带同一个 `-w`，否则会进到别的工作区的 last）：

```bash
cyan -w /home/cty/Demo/snake --continue
```

短写：`cyan -w /home/cty/Demo/snake -c`。

如果人还在第一轮那个 REPL 里没退出，就不必再启一次，直接从下面步骤 1 接着敲。

可选旁白：「接着刚才那个会话。」

Banner / 会话信息入镜停一下，能看出不是新开的空白对话。

### 步骤 1 · 列出 Skills

敲：

```
/skills
```

确认列表里有 `game-juice`。

可选旁白：「项目里已经有一个打磨小游戏体验的 Skill。」

### 步骤 2 ·（可选）看它有没有进 system prompt

时间够再敲：

```
/instructions
```

只看 `game-juice` 那一层的来源路径和字数，不要展开念正文。

### 步骤 3 · 指定下一条任务用这个 Skill

敲：

```
/skill game-juice
```

可选旁白：「下一条任务按这个 Skill 来做。」

### 步骤 4 · 发优化任务（手打，不要粘贴）

敲：

```
这个贪吃蛇已经能玩了，但看起来有点简陋。帮我按刚才那个 skill 把体验打磨一下，参考现有代码改，别推倒重写。
```

回车。

不要再补「加音效 / 最高分 / 渐变」这类细节——那些已经写在 Skill 里了。
再写一遍就看不出 Skill 的作用。第一轮 `01-初始任务.md` 里明确禁止的花活，这一轮交给 Skill 来补。

### 步骤 5 · 看它干活（不用说话）

盯这几件事入镜：

| 画面 | 展示的是 |
|---|---|
| 清单按视觉 / 音效 / 最高分等拆开 | `todo_write`（对照 Skill） |
| 改 `index.html` / `game-logic.js` 的红绿 diff | `edit_file`（对比第一轮的从零创建） |
| 若再跑测试 | `bash` 审批，再按一次 `y` |

### 步骤 6 · 对比试玩

刷新浏览器里的 `index.html`。
再玩大约 10 秒：吃食物（听音效 / 看反馈）、看分数和最高分、撞墙看死亡效果。

可选旁白：「同样的游戏，现在有渐变、音效和最高分了。」

### 步骤 7 · 收尾

切回终端，让摘要卡片入镜。

再敲：

```
/changes
```

看这一轮又改了哪些文件，定格结束。

可选旁白：「这就是 Cyan：规划、改文件、审批、再用 Skill 做第二轮打磨。」

## 两轮覆盖的特点

1. 启动 Banner（模型 / 权限 / 工作区）
2. `todo_write` 自主任务规划
3. `write_file` 创建文件的实时预览
4. `edit_file` 的 diff 高亮（第二轮）
5. `bash` 执行前的安全审批
6. 浏览器里可玩成果（两轮对比）
7. `/skills`、`/skill`、可选 `/instructions`
8. `/changes`
9. 任务完成摘要卡片
